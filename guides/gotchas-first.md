# Put the correction beside the decision

When a run exposes a mistake in the procedure, revise the step that led to it.
Give the next caller enough information to recognize the situation and choose the correct action.
Label an anticipated problem as a possibility until it has been observed.

For example, a saved skill file and a session's loaded skill can differ.
The delivery step should tell the author to inspect the launch artifact before testing the revision.
[[author-a-skill]] covers that check.

Avoid collecting unrelated warnings at the beginning of every skill.
Remove a warning when the affected operation is gone or the correction is already part of the procedure.
